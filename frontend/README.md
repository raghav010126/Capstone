# MediShield frontend

Next.js 16 (App Router) · TypeScript · Tailwind v4 · shadcn/ui (Base UI) · TanStack Query · React Flow.

## Run it
```bash
make api        # backend on :8100 (Swagger at /docs)
make web        # this app on :3000
```
`NEXT_PUBLIC_API_URL` points the app at the API (default `http://localhost:8100`). Sign in with a demo account
(`submitter`, `reviewer`, `senior`, `auditor`, `admin`; password `<name>-demo`) from the login page.

## Pages
| Route | Who | What |
|---|---|---|
| `/login` | all | credentials or one-click demo roles |
| `/` | all | KPI tiles (straight-through rate, time to decision, cost, savings) and the filterable case list |
| `/cases/new` | submitter+ | drag-and-drop upload, live pipeline graph over WebSocket (polling fallback) |
| `/cases/[id]` | all (own cases for submitters) | document viewer with zoom and evidence boxes linked to the extracted fields, collapsible per-agent panels (model, retry, tokens, cost), decision panel, override / reclassify / four-eyes approval, PDF report |
| `/review` | reviewer+ | escalations ordered by SLA, fraud risk, age; pending second approvals |
| `/audit` | auditor, senior, admin | hash-chain verification badge and a filterable event timeline |
| `/policies` | reviewer+ (upload: admin) | ingestion status, parsed exclusion table, PDF upload |
| `/insights` | reviewer+ | measured scorecard, confusion matrix, per-type accuracy, fraud scenarios, cost and latency, business impact |

## Types are generated, not written
`make web-types` dumps the API's OpenAPI schema (`frontend/openapi.json`) and generates `src/lib/api-types.ts`, so a
renamed or retyped field in the backend breaks the frontend build instead of production.

## Tests
`e2e/flow.mjs` drives the real stack in Chrome: a submitter uploads a bundle and watches the pipeline, a reviewer
reclassifies and requests an override above $10k, a senior reviewer approves it, the auditor sees the verified chain and
downloads the PDF, and role restrictions are checked in the UI (22 checks).

```bash
MEDISHIELD_LLM_OFFLINE=1 CORS_ORIGINS=http://localhost:3001 make api    # replays cached model answers: free
make web-start                                                          # production build on :3001
make e2e
```
Run it against the production build. In `next dev` React Flow's stylesheet loads in a separate chunk, so the pipeline
graph can occasionally render before its container has a size (a dev-only flake; 6/6 clean runs on the production build).
It uses the Chrome already on the machine through `playwright-core`; no browser is downloaded.

## Notes
- The repo lives in a OneDrive-synced folder, so `node_modules` and `.next` are symlinks into `~/.cache/medishield/frontend`
  (`scripts/web.sh` maintains this; always run npm through it). Turbopack refuses symlinks that leave the project, so
  the scripts use `--webpack`. On Vercel neither matters.
- React Flow's small attribution is left visible, as its licence asks unless you hold a Pro subscription.
- `AGENTS.md` / `CLAUDE.md` are generated by Next.js and tell coding agents to read the bundled docs in
  `node_modules/next/dist/docs/` first (this Next.js version differs from older ones).
